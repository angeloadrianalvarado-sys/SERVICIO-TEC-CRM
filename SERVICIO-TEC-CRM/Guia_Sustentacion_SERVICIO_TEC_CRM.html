3. Demostración Práctica del Flujo en GESTIONSERVICIOTEC.java

El método principal (main) es el hilo conductor de toda la sustentación. Muestra cómo colaboran las 30 superclases para resolver un caso real de negocio a través de 11 pasos consecutivos: 

public class GESTIONSERVICIOTEC {
    public static void main(String[] args) {

        // PASO 1: INICIALIZAR GESTORES (Infraestructura de persistencia en memoria)
        GestorServicioTecnico gestorOrdenes  = new GestorServicioTecnico(100);
        GestorClientes        gestorClientes = new GestorClientes(200);
        GestorTecnicos        gestorTecnicos = new GestorTecnicos(20);
        InventarioRepuestos   inventario     = new InventarioRepuestos(50);
        GestorPromociones     gestorPromos   = new GestorPromociones(10);
        PortalCRM             portal         = new PortalCRM(gestorOrdenes);

        // PASO 2: REGISTRAR PERSONAS Y EQUIPO FÍSICO
        Cliente cli1 = new Cliente("72938471", "Jorge Ramirez", "981234567", "jorge@gmail.com", "Calle Real 123");
        Tecnico tec1 = new Tecnico("45678901", "Adrian Alvarado", "994567812", "azalva@taller.com", "Laptops y Placas");
        Equipo  eq1  = new Equipo("Laptop", "ASUS", "TUF Gaming F15", "SN-998822", "Con cargador, sin caja");

        // PASO 3: APERTURA DE ORDEN Y PROCESAMIENTO TÉCNICO INICIAL
        OrdenServicio ord = gestorOrdenes.registrarOrden(cli1, eq1, "No da imagen en pantalla y calienta en la base");

        // PASO 4: DIAGNÓSTICO Y ASIGNACIÓN DE TÉCNICO ESPECIALISTA
        ord.asignarTecnico(tec1, "Admin");
        ord.registrarDiagnostico("Falla de chip integrado y cambio de pasta térmica", 90.0, tec1.getNombre());

        // PASO 5: DESPACHO DE REPUESTOS DESDE ALMACÉN (Validación de Stock)
        Repuesto r1 = inventario.despacharRepuesto("REP-01", 1);
        if (r1 != null) ord.agregarRepuesto(r1);

        // PASO 6: AVANCE EN LA MÁQUINA DE ESTADOS (Auditoría con Cambios y RegistroSeguimiento)
        ord.cambiarEstado(EstadoOrden.EN_REPARACION, "Reballing y reemplazo de pad termico", tec1.getNombre());
        ord.cambiarEstado(EstadoOrden.LISTO_ENTREGA, "Pruebas de estres 4K superadas", tec1.getNombre());

        // PASO 7: APLICACIÓN DE DESCUENTO POR FRECUENCIA (Motor Polimórfico de Descuentos)
        double totalFinal = gestorPromos.calcularTotalConDescuento(ord, gestorOrdenes);

        // PASO 8: EMISIÓN POLIMÓRFICA DE COMPROBANTE (Boleta Electrónica con Hash SUNAT)
        ComprobanteBase comprobante = new Boleta("B001-0001", ord, MetodoPago.YAPE, totalFinal, cli1.getId());
        comprobante.imprimirDetalle();

        // PASO 9: EMISIÓN DE PÓLIZA DE GARANTÍA (Postventa con Validez Temporal de 60 Días)
        Garantia garantia = new Garantia("GAR-001", ord, 60, "No cubre caidas ni derrame de liquidos");
        garantia.imprimirCertificado();

        // PASO 10: CONSULTA EXTERNA DESDE EL PORTAL CRM (Cliente consulta con DNI y Código)
        portal.consultarSeguimientoCliente("ORD-1001", "72938471");

        // PASO 11: GENERACIÓN DE REPORTES OPERATIVOS Y GERENCIALES
        ReporteOrden rptOrden = new ReporteOrden(ord, tec1.getNombre());
        rptOrden.imprimirDetalle();
        ReporteInventario rptInv = new ReporteInventario(inventario, "Admin", 3);
        rptInv.imprimirDetalle();
    }
}

4. Banco Maestro de Preguntas y Respuestas Técnicas para el Jurado

Cualquier integrante del equipo debe estar preparado para responder con precisión quirúrgica cualquiera de estas 12 preguntas:

P1. ¿Por qué el proyecto cuenta con 30 superclases? ¿No es sobreingeniería?
Respuesta técnica: "No, responde al Principio de Responsabilidad Única (SRP) y a la modelación granular del negocio. Dividimos el sistema en 8 dominios independientes: identidad, personas, elementos físicos, trazabilidad/órdenes, almacenamiento, descuentos, facturación y reportes. Esta jerarquía desacoplada permite que cada superclase aporte atributos y contratos específicos sin que ninguna clase asuma responsabilidades ajenas."
P2. ¿Qué diferencia conceptual y práctica existe en su código entre una Clase Abstracta y una Interfaz?
Respuesta técnica: "Una interfaz (como ICalculable o IConsultable) define un contrato puro de comportamiento: qué métodos debe implementar una clase, sin compartir estado. Una clase abstracta (como GestorBase o ComprobanteBase) modela una relación de identidad y reutilización de código: contiene atributos compartidos (capacidad, correlativo, fechas, orden asociada) y métodos concretos que sus clases hijas heredan directamente."
P3. ¿Cómo se demuestra el Polimorfismo Dinámico en el módulo de Descuentos?
Respuesta técnica: "En GestorPromociones se invoca calcularMontoDescuento() sobre la referencia abstracta Descuento. En tiempo de ejecución (Dynamic Dispatch), la JVM ejecuta la lógica concreta: si es DescuentoFrecuencia revisa el historial del cliente; si es DescuentoTemporada valida fechas festivas; y si es DescuentoPromocion corrobora el cupón. Esto cumple el Principio Abierto/Cerrado (OCP), pues podemos agregar nuevos descuentos sin modificar el gestor."
P4. ¿Por qué utilizaron arreglos estándar (Tipo[]) con contador en lugar de colecciones como ArrayList?
Respuesta técnica: "Para evidenciar control manual de estructuras de datos fundamentales y eficiencia de recursos. Al definir una capacidadMaxima y un puntero contador en GestorBase y OrdenServicio, gestionamos la memoria conscientemente, controlamos desbordamientos (overflow) e implementamos algoritmos de búsqueda lineal directa sin depender de sobrecargas de clases utilitarias externas."
P5. ¿Por qué Cambios extiende de EntidadRastreable y OrdenServicio extiende de Cambios?
Respuesta técnica: "Es una jerarquía de especialización progresiva: EntidadRastreable aporta los metadatos temporales universales (fecha de creación y si está activo). Cambios añade la máquina de estados con el arreglo de RegistroSeguimiento, costo de mano de obra y diagnóstico. Finalmente, OrdenServicio incorpora los actores de negocio: el cliente, el equipo físico, el técnico asignado y la lista de repuestos. Cada nivel añade una capa de abstracción limpia sin sobrecargar la raíz."
P6. ¿Cómo se evidencia el Principio de Inversión de Dependencias (DIP) en el PortalCRM?
Respuesta técnica: "PortalCRM no se acopla a una implementación rígida; recibe la referencia de GestorServicioTecnico a través del contrato IConsultable. Si mañana sustituimos la colección en memoria por un repositorio de base de datos MySQL o un servicio web REST, el portal continuará funcionando sin alterar su código fuente."
P7. ¿Cómo se aplica el Polimorfismo entre Boleta y Factura?
Respuesta técnica: "Ambas clases extienden de ComprobanteElectronico. En el método imprimirDetalle(), la Boleta toma el DNI de una persona natural e imprime el total con el IGV implícito; la Factura toma el RUC de un ClienteEmpresarial, desglosa formalmente la base imponible y el 18% de IGV por separado para efectos de crédito fiscal ante SUNAT."
P8. ¿Por qué la Garantía implementa la interfaz IValidable?
Respuesta técnica: "Porque una póliza de garantía está sujeta a vigencia temporal (díasValidez: 30, 60 o 90 días) y condiciones de exclusión (como daño por líquidos o sellos rotos). El método esValido() permite auditar programáticamente si el cliente tiene derecho a servicio postventa sin costo."
P9. ¿Cómo evita el sistema que se asigne un repuesto sin stock?
Respuesta técnica: "A través del método despacharRepuesto(codigo, cantidad) en InventarioRepuestos. Antes de que ord.agregarRepuesto(r) agregue el repuesto a la orden, el gestor de inventario comprueba si el stock es suficiente; si no lo es, emite una alerta y devuelve null, impidiendo inconsistencias físicas."
P10. ¿Por qué ClienteBase implementa INotificable e IValidable, pero Persona no?
Respuesta técnica: "Por el Principio de Segregación de Interfaces (ISP). Los clientes externos requieren validación de identidad (DNI o RUC) y suscripción a canales de mensajería (SMS/Email). El personal interno (técnicos, administradores) se autentica mediante legajos internos, por lo que no deben ser forzados a implementar contratos que no corresponden a su naturaleza."
P11. ¿Qué función cumple el Enum EstadoOrden en la clase Cambios?
Respuesta técnica: "Proporciona tipado fuerte (type safety). Evita el uso de cadenas de texto libres o números mágicos para definir el estado del servicio. Con el enum, solo se admiten los estados válidos (REGISTRADO, EN_DIAGNOSTICO, ESPERA_REPUESTO, EN_REPARACION, LISTO_ENTREGA, ENTREGADO, CANCELADO), previniendo estados inconsistentes."
P12. ¿Por qué DocumentoSalida es la superclase de Certificado y ReporteBase?
Respuesta técnica: "Porque ambos representan documentos oficiales generados por el sistema hacia el exterior (impresos o en pantalla). Comparten la implementación de IReportable, título, fecha de emisión y formato estandarizado de encabezado."
